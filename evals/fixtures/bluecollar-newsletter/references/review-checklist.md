# Newsletter Review Checklist

Use this checklist when reviewing drafts of Blue-Collar Engineering Dispatch newsletters.

## Structure Check

- [ ] **Title follows format**: `Blue-Collar Engineering Dispatch #N: "[Title]"`
- [ ] **Welcome section** is brief (1-2 sentences)
- [ ] **Opening story** includes:
  - [ ] Memorable company name
  - [ ] Clear setup (what they built, team size)
  - [ ] The over-engineering decision
  - [ ] Specific technical failures (not vague)
  - [ ] Resolution through simplification
  - [ ] Concrete improvement metrics
- [ ] **Transition paragraph** acknowledges the dramatization
- [ ] **Concept section** covers:
  - [ ] Overhead/complexity
  - [ ] Underutilization
  - [ ] Team/hiring impact
- [ ] **"When to use it" section** exists (fairness)
- [ ] **Hands-on tutorial** is included with runnable code
- [ ] **Takeaway** is concise (50-100 words)
- [ ] **Reader challenge** prompts engagement
- [ ] **Sign-off** uses standard format

## Voice & Tone Check

- [ ] **Conversational** - Reads like talking to a colleague
- [ ] **Self-aware** - Acknowledges story is dramatized
- [ ] **Not preachy** - Doesn't say "never use X"
- [ ] **Fair** - Acknowledges legitimate use cases
- [ ] **Technical credibility** - Shows understanding of tools critiqued
- [ ] **Rhetorical questions** used appropriately
- [ ] **No condescending language** ("obviously", "simply", etc.)

## Critical Style Rules

- [ ] **No double hyphens** - Search for `--` and remove/replace
- [ ] **Quotes only in story dialogue** - Outside the story, thoughts and ideas are expressed directly without quotation marks
- [ ] **No AI-speak** - No "Let's dive in", "It's important to note", "Furthermore", "Additionally"
- [ ] **No meta-commentary** - No "In this section we'll cover..." or "Let me explain..."
- [ ] **Signature is Bradley** - Not Brad

## Content Quality Check

- [ ] **Concrete data** - Includes statistics, studies, or metrics
- [ ] **Sources cited** - Data is attributed
- [ ] **Specific examples** - Not vague claims
- [ ] **Code is runnable** - Commands would actually work
- [ ] **No topic repetition** - Doesn't rehash previous newsletters

## Technical Accuracy

- [ ] **Tools described accurately** - No mischaracterizations
- [ ] **Tradeoffs are real** - Not strawman arguments
- [ ] **Alternative is genuinely simpler** - Not trading one complexity for another
- [ ] **Commands/code tested** - Would work if copy-pasted

## Formatting Check

- [ ] **Headers are consistent** - Using ### and #### appropriately
- [ ] **Code blocks have language tags**
- [ ] **Lists are parallel** - Consistent structure
- [ ] **Bold used for emphasis** - Key terms highlighted
- [ ] **Horizontal rules** separate major sections
- [ ] **Length is appropriate** - Total ~1500-2500 words

## Red Flags to Watch For

### Tone Problems
- "You should never use X" → Rewrite to be less prescriptive
- "Anyone who uses X is wrong" → Add nuance
- "As everyone knows..." → Remove appeal to consensus
- Excessive exclamation points → Reduce enthusiasm

### Structure Problems
- No story opening → Add fictional startup tale
- Missing "when to use it" section → Add fairness section
- Hands-on section has no code → Add practical examples
- Story has no specific failures → Add concrete technical details

### Content Problems
- Claims without data → Add sources or remove claims
- Vague complexity complaints → Get specific
- Alternative is also complex → Reconsider the argument
- Rehashing previous topic → Pivot to new angle

## Feedback Format

When providing feedback, structure it as:

```
## Summary
[1-2 sentences on overall impression]

## Strengths
- [What's working well]

## Areas to Improve
- [Specific issue] → [Suggested fix]

## Specific Line Edits
- Line X: [Current text] → [Suggested revision]
```

## Quick Pass/Fail Criteria

A newsletter is ready to publish when:
1. It has all required sections
2. Voice matches the style guide
3. It includes concrete data (at least 2-3 statistics)
4. The hands-on section has working code
5. It acknowledges when complexity IS appropriate
6. It doesn't repeat a previous topic
7. Total length is 1500-2500 words
